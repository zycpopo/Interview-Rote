## 1. STL容器了解哪些

STL容器分为三大类：顺序容器；关联容器；无序容器，再加上一类适配器。
1）顺序容器：
- vector：动态数组，连续内存存储，随机访问O(1)，尾部插入平均O(1),中间插入O(n)。
- deque：分段数组，两端插入O(1)，随机访问O(1),中间插入O(n),适合两端都要插入；
- list：双向链表，任意位置插入或者删除，不支持随机访问。迭代器不生效。
- array：编译期固定大小，零开销替代C数组，不能扩容。

2）关联容器：（红黑树）
- map：键值对，键唯一，需要为有序遍历或查询时用。
- set：只存键，自动去重排序，需要判断元素是否在其存在时且有序时可以用。
- multimap和multiset：，允许重复键。

3）无序容器：（哈希表）
- unordered_map：存键值对，平均O（1）查找和关注，在快速查找不需要有序的使用。
- unordered_set：只存键，平均O(1)判断存在性。

4）容器适配器：
- stack： 栈，后进后出，默认底层是deque；
- query：队列，先进先出，默认底层是deque；
- priority_queue：堆，默认底层是vector。

## 2. STL中allocator的作用

Allocator是STL中负责内存管理的组件，核心作用是把容器的数据结构逻辑和底层内存操作解耦。
四大核心职能：
1）allocate(n)：分配能容纳n个对象的原始内存，不调用析构函数。

2）deallocate(p，n)：释放之前分配的内存，不调用析构函数。

3）constru(p,args. . .)：在已经分配的内存地址上用placement new构造对象。

4）destroy(p)：调用对象的析构函数，但不释放内存。
前两个对应的是内存的生命周期，后两个对应的是对象生命周期。

STL中容器只关心数据结构，allocator只关心内存。两者通过模板参数绑定，互不侵入。想要更换内存策略，直接换allocator类型即可，容器部分的代码不用改。

好处就是容器可以先reserve一大块内存，需要时再逐个construct，不用每次都new或者delete。

## 3. STL中迭代器失效的场景

迭代器失效的根本原因就是内存的地址发生了变化。

1）连续内存容器：vector或者string这类连续内存存储的容器，在插入时如果触发扩容，所有迭代器全部都失效，因为vector的内存是连续的，扩容时，会new一块更大的内存，把所有的元素拷贝移动过去，然后delete旧内存，所以之前的迭代器就全部失效了；要是没扩容，插入点之后的迭代器全部失效。删除也是同理，删除元素及其之后的所有迭代器都会失效。

2）分段连续内存：插入时，在首尾插入不会使迭代器失效，在中间插入，所有迭代器都会失效。删除时同理，中间删就会全部失效。

3）链表类型存储：永远不会使任何迭代器失效，新节点的插入或者删除不影响已有或者删除后的节点的内存地址，只有被删除元素的迭代器会失效。

4）红黑树类型容器：插入时不会使任何迭代器失效，删除也只有被删除元素的迭代器失效。

5）哈希表类型容器：无序容器在插入时如果触发了refresh，也就是负载因子超过阈值，所有迭代器全部失效。不触发refresh则不失效。删除同样只有被删除元素的迭代器会失效。

Q:**循环中删除 vector 元素的正确写法？**
错误写法：
```c++
for(auto it = v.begin(); it != v.end(); ++it) 
{ 
	if(条件) v.erase(it); 
}
```
erase 后 it 已失效，再 ++it 就是未定义行为。
正确写法：
```c++
it = v.erase(it)
```
erase 返回下一个有效迭代器，不满足条件时才 `++it`。
更优雅的写法是 erase-remove 惯用法：
```c++
v.erase(std::remove_if(v.begin(), v.end(), 条件), v.end())
```
一次遍历直接搞定。

## 4. c++的map和unordered_map有什么区别和实现原理

| 维度       | `map`                | `unordered_map`    |
| -------- | -------------------- | ------------------ |
| 底层结构     | 红黑树（自平衡BST）          | 哈希表（桶数组 + 链表）      |
| 元素顺序     | 按 key 升序排列           | 无序                 |
| 查找/插入/删除 | O(logN) 稳定           | O(1) 平均，O(n) 最坏    |
| key 的要求  | 必须支持 `<` 比较（或自定义比较器） | 必须支持 `hash` 和 `==` |
| 内存开销     | 每节点 3 指针 + 颜色位，结构紧凑  | 桶数组有空槽，预留扩容空间，整体更大 |
| 迭代器失效    | 插入不失效，删除只失效被删元素      | rehash 时所有迭代器失效    |
怎么选择？
需要按key排序遍历，范围查找或者key类型没有好的哈希函数时用map。
只做点查、插入频繁、元素量大且哈希分布均匀时用unordered_map。

注意两者都不是线程安全的。`map` 结构稳定，适合读多写少场景配合 `shared_mutex`。`unordered_map` 并发写容易出问题（rehash 会让所有迭代器失效），要么分桶加锁，要么用 TBB 的 `concurrent_unordered_map`。
## 5. map,deque,list的底层实现原理

1）map：map底层是红黑树，红黑树是一种自平衡二叉搜索树，保证最长路径不超过最短路径的两倍，所有操作都是O(logN),键之间自动有序。unordered_map底层是用哈希表，桶+链表或者桶+红黑树，平均操作是O(1),但最坏O(n).

2）deque：双端队列，分段连续存储，本质是栈和队列的结合，核心结构是由一个指针map数组，每个指针指向一块固定大小的连续缓冲区，push_front/push_back 只需在当前块的前/后填充，块满了就分配新块并在中控 map 中加一个指针。随机访问：先算目标在第几个块（偏移量 / 块大小），再算块内位置（偏移量 % 块大小），两次除法就定位了，所以是 O(1)。中间插入需要移动元素，O(n)。
基本结构：
```plain
[ 指针数组 ]
    ↓      ↓      ↓
  [块A]  [块B]  [块C]
  1,2,3  4,5,6  7,8
```

3）list：双向链表每个节点独立分配，通过前驱/后继指针串联。已知迭代器位置时，插入/删除只需改指针，O(1)。但定位第 n 个元素必须从头遍历，O(n)。节点分散在堆上，缓存不友好（cache miss 多），这是 list 在现代硬件上性能差的主要原因。插入/删除不会导致其他迭代器失效。

|维度|map|deque|list|
|---|---|---|---|
|底层结构|红黑树|分段连续数组|双向链表|
|随机访问|不支持|O(1)|不支持|
|两端插入|O(log n)|O(1)|O(1)|
|中间插入|O(log n)|O(n)|O(1)(已知位置)|
|迭代器失效|删除当前才失效|头尾插入不失效，中间插入全失效|删除当前才失效|
|缓存友好|差|较好|差|
## 6. unordered_map的rehash机制

unordered_map的底层是用哈希表（就是哈希桶+链表或者红黑树）。

负载因子=当前元素量/桶数量。负载因子越高，每个桶里面连的链表或者红黑树都越长越大。查找从O(1)退化到O(n)。unordered_map设置了一个上限max_load_factor( )，如果当前的负载因子超过这个上限，

rehash的过程：首先会分配一个新的，更大的桶数组；遍历旧桶数组中所有的节点，对每个节点的key重新计算`hash(key) % new_bucket_count`,然后挂到新桶上，释放旧桶数组。整个过程是O(n),n是元素数量，这就是为什么unordered_map的插入时均摊O(1)，偶尔触发一个O(n)的rehash。

reserve和rehash的区别：`rehash(n)` 是直接设置桶数量至少为 n。`reserve(n)` 是从元素数量角度出发，保证插入 n 个元素之前不会触发 rehash，内部调用 `rehash(ceil(n / max_load_factor()))`。实际使用中，如果你知道要插入多少元素，用 `reserve` 更直观。

## 7. vector底层原理和扩容过程

底层原理：vector的底层是一块连续的内存，通过三个指针维护，分别是`_start`，`_finish`，`_end_of_storage`。
- `_start`：指向数组首位元素，begin( ）返回的就是这个指针；
-  `_finish`：指向最后一个有效元素的下一个位置，end( )返回的就是这个指针，`size( )= \_finish - \_start;`
-  `_end_of_storage`：指向已分配内存块的末尾，`capacity( ) = \_end\_of\_storage - \_start`

扩容机制：当`_finish == _end_of_storage`,说明空间已经用完了，下一次push_back就会触发扩容。完整过程如下：
1. 分配一块新内存，大小通常是原来的**2倍**（GCC的libstdc++），MSVC用的是**1.5倍**；
2. 将旧内存中的元素**逐个拷贝或移动**到新内存（如果元素有noexcept移动构造，优先移动）；
3. **释放旧内存**；
4. 更新三个指针指向新内存。
底层连续数组，预先分配容量减少扩容开销；Linux扩容2倍，Windows扩容1.5倍；扩容需要开辟新内存、拷贝全部旧数据，频繁扩容性能损耗大；随机访问效率高，但中间插入删除开销大。

## 8. push_back()和emplace_back()的区别

| 特性       | `push_back()`         | `emplace_back()`                 |
| -------- | --------------------- | -------------------------------- |
| **参数**   | 已构造好的对象，或能隐式转换为目标类型的值 | 目标类型的**构造函数参数**                  |
| **行为**   | 先构造临时对象，再**拷贝/移动**进容器 | **原地构造**（in-place），直接在容器内存位置构建对象 |
| **返回值**  | `void`                | 所插入元素的引用（C++17 起）                |
| **适用场景** | 已有对象，或简单类型            | 需要现场构造复杂对象，追求极致性能                |
**关键点：**
1. **避免临时对象**：`emplace_back` 不创建中间临时对象，对于**重型对象**（如含大量数据、文件句柄、网络连接等）能显著提升性能。
2. **参数传递**：`emplace_back` 的参数会**完美转发**（perfect forwarding）给元素类型的构造函数，所以你可以直接写构造参数，而不是先造一个对象再传进去。
3. **返回值**：C++17 起 `emplace_back` 返回插入元素的引用，方便链式使用或立即修改：
```cpp
auto& p = vec.emplace_back("Bob", 25);
p.age = 26;  // 直接修改刚插入的元素
``` 
4. **陷阱**：如果传入的参数类型和构造函数不匹配，或者存在隐式类型转换的歧义，`emplace_back` 可能编译失败或产生意外行为（因为它更"直白"地转发参数）。
**如何选择：**
- **关系**：两者都是尾部插入；`emplace_back` 是 `push_back` 的**性能增强版**。
- **选择**：如果你已经有现成的对象，两者差别不大（`push_back` 甚至可读性更好）；如果你需要**现场构造**对象，优先用 `emplace_back`，省去一次移动/拷贝。
