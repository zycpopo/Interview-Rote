## 一、14 个文件的类与职责（按层分组）

### 第 0 层：入口与公共基础（3 个文件，无业务逻辑）

| 文件                  | 类         | 行数  | 干什么                                                                                                                                    |
| ------------------- | --------- | --- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `server.hpp`        | 无         | 7   | 统一入口，只 `#include` 了 `tcp_server.hpp` 和 `network.hpp`。用户代码写 `#include "server.hpp"` 就能用所有类                                              |
| `server_common.hpp` | 无         | 47  | 所有头文件依赖（iostream、sys/epoll、sys/eventfd 等）+ 日志宏 `INF_LOG/DBG_LOG/ERR_LOG`（打印线程ID、时间、文件名、行号）。`LOG_LEVEL=DBG` 控制输出级别                      |
| `network.hpp`       | `NetWork` | 17  | 构造函数里 `signal(SIGPIPE, SIG_IGN)` 忽略 SIGPIPE。用 `static NetWork nw` 全局对象，程序一启动就自动执行。**为什么需要？** 向已关闭的 socket 写数据会触发 SIGPIPE，默认行为是杀进程，必须忽略 |

### 第 1 层：工具组件（3 个文件，被上层组合使用）

|文件|类|行数|干什么|
|---|---|---|---|
|`socket.hpp`|`Socket`|141|封装 socket 系统调用：Create/Bind/Listen/Connect/Accept/Recv/Send/Close。`NonBlockRecv/NonBlockSend` 用 `MSG_DONTWAIT` 实现非阻塞。`CreateServer` 一条龙：创建→非阻塞→绑定→监听→地址重用。`ReuseAddress` 开 `SO_REUSEADDR+SO_REUSEPORT`|
|`buffer.hpp`|`Buffer`|121|可扩容读写缓冲区。底层 `vector<char>` + `_reader_idx` + `_writer_idx` 双偏移。`EnsureWriteSpace` 智能扩容：先看尾部空闲够不够，不够就把数据搬到头部（compact），还不够才 resize。提供 `GetLine/FindCRLF` 按行读取（HTTP 解析用）|
|`any.hpp`|`Any`|56|类型擦除容器（类似 `std::any`）。用 `holder` 基类 + `placeholder<T>` 子类实现，能存任意类型。**Connection 的 `_context` 就是 Any**，用来保存协议相关上下文（比如 HTTP 解析状态），Upgrade 切换协议时替换|

### 第 2 层：事件驱动核心（3 个文件，Reactor 的心脏）

|文件|类|行数|干什么|
|---|---|---|---|
|`channel.hpp`|`Channel`|56|封装 **一个 fd + 关注的事件 + 5 个回调**。`_events` 是想监控的事件（EPOLLIN/EPOLLOUT），`_revents` 是实际就绪的事件。5 个回调：读/写/错误/关闭/任意事件。`EnableRead/EnableWrite/DisableWrite` 修改 `_events` 后调 `Update()` 注册到 epoll。`HandleEvent()` 根据 `_revents` 分发到对应回调|
|`poller.hpp`|`Poller`|77|**epoll 的直接封装**。`epoll_create` 创建实例，`epoll_ctl` 做 ADD/MOD/DEL，`epoll_wait` 等就绪。内部维护 `unordered_map<int, Channel*>` 做 fd→Channel 映射。`Poll()` 返回就绪的 Channel 列表（通过 `_revents` 回填实际事件）|
|`event_loop.hpp`|`EventLoop`|127|**事件循环**。成员：`_thread_id`（判断当前线程）、`_event_fd`（唤醒用）、`_event_channel`（eventfd 的 Channel）、`_poller`、`_tasks`（任务队列）、`_mutex`、`_timer_wheel`。`Start()` 是三步死循环：`Poll()` → `HandleEvent()` → `RunAllTask()`。`RunInLoop`（当前线程直接执行，否则投递）/ `QueueInLoop`（投递+唤醒）。这个文件还实现了 `Channel::Remove/Update` 和 `TimerWheel` 的外部方法（因为跨类依赖，放在这里）|

### 第 3 层：定时与线程（2 个文件）

|文件|类|行数|干什么|
|---|---|---|---|
|`timer.hpp`|`TimerTask` + `TimerWheel`|120|**时间轮定时器**。`TimerTask` 是单个定时任务（id+超时时间+回调+取消标记），析构时如果没取消就执行回调。`TimerWheel` 是 60 槽的环形数组，每槽存 `shared_ptr<TimerTask>` 列表。用 `timerfd` 每秒触发，秒针走一格，`clear()` 对应槽 → shared_ptr 释放 → TimerTask 析构 → 执行任务。`_timers` 是 `id→weak_ptr` 映射，用于 Refresh/Cancel。所有操作通过 `RunInLoop` 投递到 EventLoop 线程|
|`thread_pool.hpp`|`LoopThread` + `LoopThreadPool`|68|**工作线程池**。`LoopThread` 封装一个线程+一个 EventLoop，用条件变量同步（确保 EventLoop 创建好才返回指针）。`LoopThreadPool` 创建 N 个 LoopThread，`NextLoop()` 用 round-robin 返回。`thread_count=0` 时返回 baseloop（单线程模式）|

### 第 4 层：连接与服务器（3 个文件，业务组装）

| 文件               | 类            | 行数  | 干什么                                                                                                                                                                                                                                                                                                                                            |
| ---------------- | ------------ | --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `acceptor.hpp`   | `Acceptor`   | 41  | **监听器**。组合 Socket + Channel。构造时 `CreateServer` 创建监听 socket，设置读回调=HandleRead。`HandleRead` 里 `accept` 得到新 fd，调用 `_accept_callback(newfd)`。`Listen()` 启动读事件监控。**注意**：必须先 SetAcceptCallback 再 Listen，否则可能 accept 到连接但回调还没设置，资源泄漏                                                                                                                   |
| `connection.hpp` | `Connection` | 203 | **TCP 连接管理**（全场最大最核心的类）。继承 `enable_shared_from_this`。成员：`_conn_id`、`_sockfd`、`_statu`（四状态）、`_socket`、`_channel`、`_in_buffer`/`_out_buffer` 双缓冲、`_context`（Any）、5 个回调。核心：HandleRead/HandleWrite/HandleClose/HandleEvent、EstablishedInLoop、SendInLoop、ShutdownInLoop、ReleaseInLoop。**所有公开方法都通过 RunInLoop/QueueInLoop 投递到所属 EventLoop 线程**，保证线程封闭 |
| `tcp_server.hpp` | `TcpServer`  | 74  | **服务器组装**（用户直接用的类）。成员：`_baseloop`（主线程 EventLoop）、`_acceptor`、`_pool`（线程池）、`_conns`（`map<id, PtrConnection>` 管理所有连接）。`NewConnection` 创建 Connection 并 round-robin 分配 EventLoop。`RemoveConnection` 通过 `baseloop.RunInLoop` 移除（保证 _conns 只由主线程操作）。`Start()` 创建线程池 + 启动 baseloop                                                                    |

## 二、谁持有谁（组合关系图）

```
TcpServer
├── _baseloop (EventLoop)          ← 主线程事件循环
│   ├── _poller (Poller)           ← epoll
│   ├── _event_fd + _event_channel ← 唤醒机制
│   ├── _tasks + _mutex            ← 跨线程任务队列
│   └── _timer_wheel (TimerWheel)  ← 时间轮（内含 timerfd + channel）
├── _acceptor (Acceptor)           ← 监听器
│   ├── _socket (Socket)           ← listenfd
│   └── _channel (Channel)         ← listenfd 的事件管理
├── _pool (LoopThreadPool)
│   └── _threads[] (LoopThread)    ← 每个工作线程
│       └── _loop (EventLoop)      ← 工作线程事件循环（结构同 baseloop）
└── _conns (map<id, PtrConnection>)
    └── Connection[]               ← 每个连接
        ├── _socket (Socket)       ← 连接 fd
        ├── _channel (Channel)     ← 连接 fd 的事件管理
        ├── _in_buffer (Buffer)    ← 接收缓冲
        ├── _out_buffer (Buffer)   ← 发送缓冲
        └── _context (Any)         ← 协议上下文
```

**关键观察**：每个 EventLoop 都有自己的 Poller（epoll 实例）。主线程的 epoll 只监听 listenfd + eventfd + timerfd；工作线程的 epoll 监听分配给它的连接 fd + 自己的 eventfd + timerfd。这就是"每个线程一个 epoll"的主从 Reactor。

## 三、7 条核心调用链（面试按这个讲）

### 链 1：启动流程

```
TcpServer(port) 构造
  → _baseloop 构造（创建 eventfd + Poller + TimerWheel）
  → _acceptor 构造（CreateServer 创建 listenfd + Channel，设置读回调）
  → _acceptor.SetAcceptCallback(&TcpServer::NewConnection)
  → _acceptor.Listen() → Channel.EnableRead() → Poller.UpdateEvent(ADD)
TcpServer.Start()
  → _pool.Create() → 创建 N 个 LoopThread → 每个线程内 new EventLoop + Start()
  → _baseloop.Start() → 进入三步死循环
```

### 链 2：新连接建立（主线程 → 工作线程）

```
baseloop: epoll_wait 返回 listenfd 就绪
→ Channel::HandleEvent → Acceptor::HandleRead
→ Socket::Accept() 得到 newfd
→ TcpServer::NewConnection(newfd)
→ _pool.NextLoop() round-robin 选一个工作线程 EventLoop
→ new Connection(loop, id, fd) → 设置 5 个回调
→ conn->Established() → loop->RunInLoop(EstablishedInLoop)
  → 【切到工作线程】状态 CONNECTING→CONNECTED
  → Channel.EnableRead() 注册到工作线程的 epoll
  → 调用 connected_callback
→ _conns.insert(id, conn)  （主线程操作，无锁）
```

### 链 3：数据接收（工作线程内）

```
工作线程: epoll_wait 返回连接 fd 的 EPOLLIN
→ Channel::HandleEvent → Connection::HandleRead
→ Socket::NonBlockRecv(buf, 65535)  （非阻塞，一次读 64K）
→ _in_buffer.WriteAndPush(buf, ret)  （写入接收缓冲）
→ _message_callback(shared_from_this(), &_in_buffer)  （调业务回调）
→ HandleEvent 里如果启用了非活跃释放：TimerRefresh(conn_id) 延迟超时
```

### 链 4：数据发送（可能跨线程）

```
业务线程调 conn->Send(data, len)
→ 创建临时 Buffer，拷入数据（防止 data 是临时空间被释放）
→ loop->RunInLoop(SendInLoop, std::move(buf))
  → 如果当前就是工作线程：直接执行
  → 如果是其他线程：QueueInLoop 投递 + WeakUpEventFd 唤醒
→ 【工作线程】SendInLoop：_out_buffer.WriteBufferAndPush(buf)，Channel.EnableWrite()
→ 工作线程 epoll_wait 返回 EPOLLOUT
→ Connection::HandleWrite → Socket::NonBlockSend(out_buffer)
→ _out_buffer.MoveReadOffset(ret)
→ 发完了 → Channel.DisableWrite() （LT 模式防忙等）
→ 如果状态是 DISCONNECTING → Release()
```

### 链 5：连接关闭（半关闭 → 释放）

```
对端关闭 → HandleRead 里 recv 返回 0 → ShutdownInLoop
→ 状态 CONNECTED→DISCONNECTING
→ 如果 in_buffer 还有数据 → 先调 message_callback 处理完
→ 如果 out_buffer 还有数据 → EnableWrite 等发完再 Release
→ 如果 out_buffer 空 → 直接 Release()
→ Release() → loop->QueueInLoop(ReleaseInLoop)
  → 【工作线程】状态→DISCONNECTED，Channel.Remove()，Socket.Close()
  → 取消定时器，调 closed_callback，调 server_closed_callback
→ server_closed_callback → TcpServer::RemoveConnection
→ baseloop.RunInLoop(RemoveConnectionInLoop)
  → 【主线程】_conns.erase(id) → shared_ptr 引用计数到 0 → Connection 析构
```

### 链 6：定时器（时间轮）

```
TimerWheel 构造时：timerfd_create（每秒超时）+ Channel 注册到 EventLoop
每秒 timerfd 可读 → OnTime → ReadTimefd 得到超时次数
→ 循环 times 次 RunTimerTask
→ _tick = (_tick+1) % 60，_wheel[_tick].clear()
→ shared_ptr 释放 → TimerTask 析构
→ TimerTask 析构：没 canceled 就执行 _task_cb（比如 Connection::Release）
→ 然后 _release 从 _timers 移除 id 映射

非活跃释放链路：
EnableInactiveRelease(10) → TimerAdd(conn_id, 10, Release)
每次 HandleEvent → TimerRefresh(conn_id) → 重新插入到 (_tick+10) 槽
10 秒无事件 → 时间轮到该槽 → clear → TimerTask 析构 → Release
```

### 链 7：跨线程唤醒（eventfd 机制）

```
线程A 调 loop->QueueInLoop(cb)
→ mutex 加锁，_tasks.push_back(cb)，解锁
→ WeakUpEventFd() → write(eventfd, &val, 8) 写一个 uint64
→ 【工作线程】epoll_wait 被 eventfd 的 EPOLLIN 唤醒
→ Channel::HandleEvent → ReadEventfd → read(eventfd) 读走数据
→ RunAllTask → mutex 加锁，_tasks.swap(局部 vector)，解锁
→ 逐个执行任务（此时已无锁，因为 swap 后任务池空了）
```

## 四、面试一句话总结模块协作

> **Socket 管 fd，Buffer 管数据，Channel 管事件回调，Poller 管 epoll，EventLoop 把它们串成三步循环，TimerWheel 用 timerfd 做定时，LoopThreadPool 提供多 EventLoop，Acceptor 负责 accept，Connection 管一条连接的生命周期，TcpServer 把所有组件组装起来并管理连接表。**
