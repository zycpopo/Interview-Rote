在Reactor模式中，Connection也就是Tcp连接类是应用层业务逻辑与底层网络I/O下之间最核心的桥梁。它负责的是单个Tcp Socket的全生命周期，包括建立连接、非阻塞读写、协议切换、非活跃超时剔除、半关闭并断开。

## 一、代码拆解

`Connection` 继承自 `std::enable_shared_from_this<Connection>`，这保证了在其异步回调和跨线程投递任务时，可以通过 `shared_from_this()` 安全地延续自身的生命周期，避免在回调执行过程中对象被意外销毁（悬挂指针问题）。

### 1.核心成员变量
```c++
class Connection : public std::enable_shared_from_this<Connection> {
    private:
        uint64_t _conn_id;              
        // 连接的唯一 ID，便于 TcpServer 管理和定时器检索
        int _sockfd;                    // 连接对应的文件描述符
        bool _enable_inactive_release;  // 是否开启非活跃连接超时销毁标志
        EventLoop *_loop;               
        // 连接所绑定的从属 EventLoop (One Loop Per Thread)
        ConnStatu _statu;               
        // 连接状态：DISCONNECTED, CONNECTING, CONNECTED, DISCONNECTING
        Socket _socket;                 // Socket 操作封装
        Channel _channel;               
        // 事件通道（封装 connfd 的读写事件与回调）
        Buffer _in_buffer;              
        // 应用层接收缓冲区（保存从 Socket 读出的数据）
        Buffer _out_buffer;             
        // 应用层发送缓冲区（保存待写回 Socket 的数据）
        Any _context;                   
        // 协议/业务上下文容器（类型擦除，可挂载任意自定义数据）

        /* 组件使用者（上层业务）注册的回调 */
        ConnectedCallback _connected_callback; // 建连完成回调
        MessageCallback _message_callback;     // 收到数据回调
        ClosedCallback _closed_callback;       // 连接关闭回调
        AnyEventCallback _event_callback;     // 任意事件触发回调

        /* 框架内部注册的回调 */
        ClosedCallback _server_closed_callback;// 通知 TcpServer 从哈希表中移除该连接
};
```

### 2.核心私有处理函数

1. 读事件处理：HandleRead( )
```c++
void HandleRead() {
    char buf[65536];
    // 1. 非阻塞读取 Socket 接收缓冲区的数据
    ssize_t ret = _socket.NonBlockRecv(buf, 65535);
    if (ret < 0) {
        // 读取出错，不能直接硬关闭，需优雅关闭（处理剩余缓冲区数据）
        return ShutdownInLoop();
    }
    // 2. 将数据追加到应用层输入缓冲区 _in_buffer
    _in_buffer.WriteAndPush(buf, ret);

    // 3. 如果读到了数据，回调上层的 _message_callback 进行业务解析
    if (_in_buffer.ReadAbleSize() > 0) {
        return _message_callback(shared_from_this(), &_in_buffer);
    }
}
```

2. 写事件处理：Handle Write ( )
```c++
void HandleWrite() {
    // 1. 将应用层发送缓冲区 _out_buffer 中的数据非阻塞发送出去
    ssize_t ret = _socket.NonBlockSend(_out_buffer.ReadPosition(), _out_buffer.ReadAbleSize());
    if (ret < 0) {
        // 发送出错：若接收缓冲区还有数据先让上层处理，随后强制释放连接
        if (_in_buffer.ReadAbleSize() > 0) {
            _message_callback(shared_from_this(), &_in_buffer);
        }
        return Release();
    }
    _out_buffer.MoveReadOffset(ret); // 移动读指针

    // 2. 如果发送缓冲区清空了，立刻关闭写事件监控，避免 epoll 忙等 (Busy Loop)
    if (_out_buffer.ReadAbleSize() == 0) {
        _channel.DisableWrite();
        // 如果连接当前处于待关闭状态（DISCONNECTING），数据发完后立刻释放
        if (_statu == DISCONNECTING) {
            return Release();
        }
    }
}
```

3. 资源释放：RelaseInloop( )
```c++
void ReleaseInLoop() {
    // 1. 状态置为 DISCONNECTED
    _statu = DISCONNECTED;
    // 2. 移除底层 Poller 的事件监控
    _channel.Remove();
    // 3. 关闭系统 Socket 文件描述符
    _socket.Close();
    // 4. 取消定时器中的非活跃超时任务
    if (_loop->HasTimer(_conn_id)) CancelInactiveReleaseInLoop();
    // 5. 先回调用户的关闭回调，再回调 TcpServer 的移除回调
    if (_closed_callback) _closed_callback(shared_from_this());
    if (_server_closed_callback) _server_closed_callback(shared_from_this());
}
```

4. 协议热切换：UpgradeInLoop( )
```c++
void UpgradeInLoop(const Any &context, ...) {
    _context = context;
    _connected_callback = conn;
    _message_callback = msg;
    _closed_callback = closed;
    _event_callback = event;
}
```


## 3.核心共有API

为了保证线程安全，所有外部调用，比如Send、Shutdown、EnableInactiveRelease，都会通过_loop->RunInLoop( )或者_loop->QueueInLoop( )强行打包并投递给Connection绑定的哪个EventLoop线程中串行执行。

- **`Send(const char *data, size_t len)`**： 将传入的 `data` 写入临时的 `Buffer`（避免外部传入的指针在异步执行前被释放），然后通过 `RunInLoop` 投递 `SendInLoop`。在 `SendInLoop` 中把数据放入 `_out_buffer` 并调用 `_channel.EnableWrite()` 开启写事件监控。

- **`Shutdown()`**： 优雅关闭连接。首先置状态为 `DISCONNECTING`，如果还有数据未发送，等 `HandleWrite()` 把数据全部发完后再释放；如果没有数据，则直接释放。

- **`Upgrade(...)`**： 重置上下文与各类回调。此接口要求必须在 Loop 线程内同步执行（通过 `_loop->AssertInLoop()` 断言），防止切换协议过程中有新事件触发导致用旧协议解析了新数据（比如 HTTP 升级为 WebSocket）。

### 二、 Connection 的工作流程

以下是一个完整的 TCP 连接从诞生到销毁的全生命周期流程：

```Plaintextx
[新建连接] ───► 1. TcpServer 构造 Connection (状态: CONNECTING)
                      │
                      ▼
               2. 绑定 EventLoop，设置业务回调
                      │
                      ▼
               3. Connection::Established() ───► 状态切换为 CONNECTED
                                            ───► _channel.EnableRead() (开启 epoll 读事件)
                                            ───► 触发 _connected_callback()

================================ 正常数据通信阶段 ==================================

[数据到达] ─► Poller 触发读事件 ─► Channel::HandleEvent() ─► Connection::HandleRead()
	                                                        │
                                                            ├─► Recv 到 _in_buffer
                                                            ├─► 触发 HandleEvent() 
	                                                        \\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\    定时器
                                                            └─► message_callback()
                                                            
[数据发送] ─► 用户调用 conn->Send() ─► QueueInLoop(SendInLoop) ─► 写入 _out_buffer
                                                                            │
                                                                            ▼
                                                            _channel.EnableWrite()
                                                                            │
                                                                            ▼
                                                                  Poller 触发写事件
                                                                            │
                                                                            ▼
                                                        Connection::HandleWrite()
                                                                            │
                                                                            ▼
                                                        发送：  DisableWrite()

=============================== 连接销毁阶段 ====================================

[断开连接] ───► (情况A: 对端关闭/出错/超时) OR (情况B: 用户主动 Shutdown)
                      │
                      ▼
               状态设为 DISCONNECTING
                      │
                      ▼
               检查 _out_buffer 是否有剩余数据？
               ├── 有数据 ──► 继续写，发完后触发 Release()
               └── 无数据 ──► 直接触发 Release()
                                  │
                                  ▼
                        Connection::ReleaseInLoop()
                                  │
                                  ├─► _channel.Remove() (从 epoll 移除)
                                  ├─► _socket.Close()  (关闭 fd)
                                  ├─► 取消 TimerWheel 定时器
                                  ├─► 触发用户 _closed_callback()
                                  └─► 触发 _server_closed_callback() (从 TcpServer 的 map 中删除)
```

### 三、 实现原理与核心设计思想

#### 1. 异步非阻塞 + 应用层缓冲（Output Buffer 的本质）

在传统的阻塞 Socket 中，`send()` 会一直阻塞直到数据写入内核。但在非阻塞 I/O 中：

- 如果内核 Socket 发送缓冲区满了，`send()` 会立即返回 `EAGAIN` 或写入部分字节。
    
- `Connection` 引入了 `_out_buffer`：当一次性没发完数据时，把剩余数据追加到 `_out_buffer` 并**向 Poller 注册 `EPOLLOUT`（写事件）**。
    
- 当内核 Socket 缓冲区重新变为空闲时，`epoll` 唤醒并触发 `HandleWrite()` 继续发送。发完后再取消写事件。
    
- **好处**：应用层线程完全不需要等待，实现了彻底的异步非阻塞发送。
    

#### 2. 无锁化串行设计（Thread-per-Loop 安全保证）

所有的 Socket 读写、缓存修改、事件变更和状态切换，都绝对不会加锁。

- 因为 `Connection` 内的一切方法最终都通过 `_loop->RunInLoop()` 强制打包放到该连接所属的 `EventLoop` 线程内运行。
    
- 这消除了多线程竞态条件，同时极大提高了网络库的吞吐性能。
    

#### 3. 基于时间轮的非活跃超时销毁（Keep-Alive / Inactive Release）

- 每次套接字有任何事件发生时（读、写、错误），都会触发 `HandleEvent()`。
    
- `HandleEvent()` 内部会检查 `_enable_inactive_release`，若为 `true` 则调用 `_loop->TimerRefresh(_conn_id)`。
    
- 只要客户端一直在发送/接收数据，该连接在 `TimerWheel`（时间轮）中的定时任务就会一直被延后刷新；一旦客户端长时间无通信（超时），时间轮自动触发 `Connection::Release()` 释放该连接，有效防止了无用连接占用系统 fd 资源。
    

#### 4. 类型擦除的连接上下文 (`Any _context`)

- 网络库本身是通用的，不关心应用层是 HTTP、WebSocket 还是私有 RPC 协议。
    
- `Connection` 内部包含一个 `Any _context` 成员。应用层可以在 `_connected_callback` 中给它挂载一个自定义解析器（如 `HttpTaskContext`），在 `_message_callback` 中通过 `_context.get<HttpTaskContext>()` 取出来维护协议解析的状态机。
