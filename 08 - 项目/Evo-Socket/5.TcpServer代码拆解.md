### 一、 `TcpServer` 的核心代码拆解

#### 1. 核心成员变量

```c++
class TcpServer {
    private:
        uint64_t _next_id;              // 自动增长的连接 ID（保证全局唯一）
        int _port;                      // 服务器监听的端口
        int _timeout;                   // 非活跃连接超时时间（秒）
        bool _enable_inactive_release;  // 是否开启非活跃超时剔除

        EventLoop _baseloop;            
        // 【主 Reactor】：跑在主线程，专门负责监听 ListenSocket 的新连接
        Acceptor _acceptor;            
        // 连接接收器：封装了 Listen Socket 的创建、绑定和 accept 过程
        LoopThreadPool _pool;           
        // 【从属 Reactor 线程池】：跑在子线程，专门负责已建立 Connection 的数据读写

        std::unordered_map<uint64_t, PtrConnection> _conns; 
        // 全局连接哈希表：管理所有存活 connection 的生命周期

        /* 上层业务注册的回调函数 */
        ConnectedCallback _connected_callback; // 连接建立完成回调
        MessageCallback _message_callback;     // 收到消息回调
        ClosedCallback _closed_callback;       // 连接关闭回调
        AnyEventCallback _event_callback;     // 任意事件回调
};
```

#### 2. 核心私有函数拆解（组装逻辑的核心）

##### ① 构造函数：零零件装配

在 `TcpServer` 构造时，整个服务器的雏形就已经搭建完成了：

```c++
TcpServer(int port):
    _port(port), 
    _next_id(0), 
    _enable_inactive_release(false), 
    _acceptor(&_baseloop, port),  // 1. 将 Acceptor 挂载到主 Reactor (baseloop) 上
    _pool(&_baseloop)             // 2. 将主 Reactor 关联到线程池中
{
    // 3. 给 Acceptor 设置回调：一旦有新连接建立，触发 TcpServer::NewConnection()
    _acceptor.SetAcceptCallback(std::bind(&TcpServer::NewConnection, this, std::placeholders::_1));
    
    // 4. 将监听套接字(listenfd)的读事件注册到 baseloop 的 Poller 中，开启监听
    _acceptor.Listen();
}
```

##### ② 新连接处理：`NewConnection(int fd)`

当客户端发起 `connect` 时，主 Reactor 唤醒 `Acceptor` 执行 `accept` 得到 `fd`，随后回调 `NewConnection`。这是**主从 Reactor 交接**最关键的代码：

```C++
void NewConnection(int fd) {
    _next_id++;
    
    // 1. 从线程池中通过 Round-Robin 算法挑选一个从属 EventLoop (subloop)
    // 2. 用挑选出的 subloop、新的 connfd 和 _next_id 构造一个 Connection 对象
    PtrConnection conn(new Connection(_pool.NextLoop(), _next_id, fd));
    
    // 3. 将 TcpServer 收集到的用户业务回调，全量设置给这个 Connection
    conn->SetMessageCallback(_message_callback);
    conn->SetClosedCallback(_closed_callback);
    conn->SetConnectedCallback(_connected_callback);
    conn->SetAnyEventCallback(_event_callback);
    
    // 4. 设置框架内部的回调：当连接要断开时，通知 TcpServer 清理哈希表
    conn->SetSrvClosedCallback(std::bind(&TcpServer::RemoveConnection, this, std::placeholders::_1));
    
    // 5. 若开启了超时剔除，为 Connection 启动定时器
    if (_enable_inactive_release) conn->EnableInactiveRelease(_timeout);
    
    // 6. 启动 Connection 的初始化（在对应的 subloop 线程中将 connfd 的读事件注册进 Poller）
    conn->Established();
    
    // 7. 用 shared_ptr 将 Connection 存入全局 _conns 哈希表中（防止 Connection 被 Premature 释放）
    _conns.insert(std::make_pair(_next_id, conn));
}
```

##### ③ 连接移除：`RemoveConnection(const PtrConnection &conn)`

当客户端断开连接或超时释放时，`Connection` 内部触发该回调：

```C++
void RemoveConnectionInLoop(const PtrConnection &conn) {
    int id = conn->Id();
    auto it = _conns.find(id);
    if (it != _conns.end()) {
        _conns.erase(it); // 从 unordered_map 中抹去 shared_ptr 节点
    }
}

void RemoveConnection(const PtrConnection &conn) {
    // 强制切回主 Reactor 线程(baseloop)执行清理，保证对 _conns 的修改是绝对线程安全的！
    _baseloop.RunInLoop(std::bind(&TcpServer::RemoveConnectionInLoop, this, conn));
}
```

##### ④ 启动服务：`Start()`

整台服务器的“引擎点火”：

```C++
void Start() { 
    _pool.Create();    // 1. 启动子线程池，实例化各个 LoopThread，开启从属 Reactor 循环
    _baseloop.Start(); // 2. 主 Reactor 开启无限循环（主线程挂起在 baseloop 的 epoll_wait 上）
}
```

### 三、 关键架构设计与逻辑思考

#### 1. 主从 Reactor 模式 (Main-Sub Reactor) 的高效分工

- **主 Reactor (`baseloop`)**：只干一件事——**专职接客**。通过 `Acceptor` 监听 `listenfd`，任何新的客户端连接来了，第一时间 `accept` 下来，然后打包成 `Connection` 甩给子线程。主线程绝不干任何业务处理和 Socket 数据读写，因此它极难被阻塞，能保证极高的 TCP 并发握手响应速度。
    
- **从属 Reactor (`LoopThreadPool`)**：负责**具体干活**。线程池里的各个 `SubLoop` 分别管理着一批分配给自己的 `Connection`。每个连接的数据读取、协议解析、业务回调和写回响应，全部在各自对应的从属线程中独立完成。
    

#### 2. 生命周期管理的绝妙之处（`_conns` 集中管理）

C++ 异步编程中最头疼的就是对象生命周期的管理（比如：当线程正在读取 Socket 数据时，连接突然被外部释放掉了怎么办？）。

- `TcpServer` 内部用 `std::unordered_map<uint64_t, PtrConnection>` 持有每一个连接的 `std::shared_ptr`。
    
- 只要连接还在通畅通信，`_conns` 中就保留着一份强引用，连接对象 `Connection` 就绝对不会被析构。
    
- 当连接触发关闭或出错时，`Connection` 执行完所有的清理回调后，最后调用 `_server_closed_callback`，通知 `TcpServer` 将其从 `_conns` 中 `erase` 掉。引用计数归零，`Connection` 才会被安全平滑地销毁。
    

#### 3. 跨线程操作的无锁化闭环

- 增加新连接 `NewConnection()`：发生在主线程 `baseloop` 中，向 `_conns` 写入节点。
    
- 删除连接 `RemoveConnection()`：虽然是在 `SubLoop` 线程检测到的连接断开，但通过 `_baseloop.RunInLoop()`，将“删除哈希表节点”这一任务**切回主线程去执行**。
    
- **总结**：`_conns` 哈希表所有的增删查改全部在 `baseloop` 主线程中串行化完成，因此 `_conns` 甚至**不需要加任何互斥锁**！
    

### 四、 总结：框架的运行全景故事

1. **用户层面**：实例化 `TcpServer server(8080)`，设置处理业务的回调函数，调用 `server.Start()`。
    
2. **底层就绪**：`TcpServer` 开启主 `baseloop` 监听 8080 端口，并创建若干 `LoopThread` 子线程等待分发。
    
3. **连接到来**：客户端 `connect` 8080 $\rightarrow$ `Acceptor` 响应 $\rightarrow$ `TcpServer::NewConnection()` 被触发。
    
4. **任务分派**：`TcpServer` 算出一个闲置的子线程 `SubLoop`，把新套接字组装成 `Connection` 放入 `_conns` 并交给这个 `SubLoop`。
    
5. **业务运转**：客户端发送请求数据 $\rightarrow$ `SubLoop` 的 `Poller` 被唤醒 $\rightarrow$ `Connection` 读数据入 `Buffer` $\rightarrow$ 回调用户的业务代码进行处理。
    
6. **优雅销毁**：客户端断开 $\rightarrow$ `Connection` 读到 EOF $\rightarrow$ 清理事件注册 $\rightarrow$ 通知 `TcpServer` 从 `_conns` 清除引用 $\rightarrow$ 对象安全析构。
